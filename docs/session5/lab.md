# 5회차 실습 — Agentic 루프 · Self-Query · 계산 Tool

수업은 지난 시간과 같이 "강사가 짧게 보여 주고 → 여러분이 직접 채우고 → 테스트로 확인"입니다. 오늘은 채우는 자리가 넷(**실습 1** 둘, **실습 2** 하나, **실습 3** 하나)이고, 측정이 둘(**실측 1** 10문항, **실측 2** 40문항과 적대적 5문항)입니다. 결과물은 `results/agentic.json` 입니다. 3회차 baseline, 4회차 hybrid 와 같은 40문항을 같은 자로 잰 숫자에, 오늘은 **답변률 · 오거절률 · 미답변 정확도**가 더해집니다. 아래는 수업 순서대로 적은 것입니다.

**이 문서에서 쓰는 명령**

| 명령 | 하는 일 |
|---|---|
| `make test` | 자동 채점. 2~4회차 검사 51개와 오늘 검사 51개를 한 번에 돌려서 맞으면 초록, 틀리면 빨강 |
| `make graph` | 에이전트 그래프의 상태도를 mermaid 텍스트로 찍는다. 그림을 손으로 그리지 않는다 |
| `make ask Q="질문"` | 질문 하나를 에이전트에 넣고 지나간 노드 · 뽑힌 필터 · 판정 · 재검색 횟수 · 근거 · 계산 · 답변을 본다 |
| `make agentic-sample` | 골든셋 앞 10문항을 에이전트로 푼다. 약 2~3분. 결과는 `results/agentic_sample.json` |
| `make agentic` | 40문항 전부. **오늘의 결과물** `results/agentic.json`. 약 12분이라 휴식에 돌린다 |
| `make adversarial` | 적대적 문항 5개를 넣고 "하지 말았어야 할 것"이 나타났는지 본다. `results/adversarial.json` |
| `make check-s05` | 오늘 결과물이 조건 5개를 만족하는지 검사한다. 과제 확인도 이 명령으로 |

Windows 는 [install.md](../install.md) 의 PowerShell 명령을 씁니다. `make ask` 는 `.venv\Scripts\python scripts\ask.py "질문"` 입니다.

## 오늘 끝내고 갈 것

1. 4회차까지의 검색은 **무조건 상위 몇 개를 넘겼습니다.** 오늘은 넘기기 전에 근거가 충분한지 **판정**하고, 부족하면 질문을 고쳐 **다시** 검색하고, 없으면 **거절**합니다. 다시 검색하는 횟수에 **상한**을 둡니다.
2. LLM 이 질문에서 필터(발행사 · 문서 종류 · 기준일)를 뽑아 4회차의 필터 자리에 넣습니다(**Self-Query**). 4회차 끝에 사람이 넣던 `--issuer`, `--latest` 가 자동이 됩니다.
3. 계산 질문은 **LLM 이 계산하지 않습니다.** 문서에서 요율·구간·최저이율을 뽑기만 하고, 계산은 순수 함수가 합니다. 산식이 세 가지인 중도해지이율로 그 이유를 봅니다.

## 1부 · 고정 파이프라인의 한계, 자기교정 루프

노트북 `notebooks/s05_agent.ipynb` 셀 1~3. 셀 번호는 코드 셀 첫 줄의 `# [셀 N]` 표시입니다. 이 노트북은 Qdrant 를 열지 않으므로 터미널과 같이 써도 됩니다.

4회차 `make hybrid` 뒤에도 상위 5개 밖인 문항이 9개였고, 미답변형 2문항은 어떤 검색도 못 찾습니다. 그런데 4회차 검색은 그 문항에도 상위 8개를 그대로 넘깁니다. 근거가 없는데도 답변 노드에 들어가면 모델은 그럴듯한 문장을 만듭니다. **금융 답변에서 틀린 답은 답이 없는 것보다 나쁩니다.** 그래서 검색과 답변 사이에 노드를 셋 더 넣습니다.

```
preprocess → rewrite → selfquery → retrieve → grade ─┬─ sufficient   → calc → answer
                            ↑                        ├─ insufficient → (retry_count < 상한) bump_retry ─┘
                            └────────────────────────┘                  (상한에 닿으면) → answer (한계를 밝힘)
                                                      └─ none         → abstain
```

| 노드 | 하는 일 | 상태 |
|---|---|---|
| `preprocess` | 질문에서 주민번호·계좌번호·카드번호·전화번호를 가린다(정규식, `policy.yaml`) | 완성본 |
| `rewrite` | 사용자의 말을 문서의 말로 고쳐 쓴다("리볼빙" → "일부결제금액이월약정"). 재검색이면 다른 표현을 시도 | 완성본 |
| `selfquery` | 질문에서 필터를 뽑는다 | **실습 2** |
| `retrieve` | 4회차 Hybrid + 리랭커. 재작성 검색어와 원 질문 둘 다로 찾아 RRF 로 합치고, 순서는 원 질문 기준으로 리랭크. 필터가 0건이면 한 단계씩 푼다(`relax`). "현행"이면 최신 판본만(`pick_latest`) | 완성본 |
| `grade` | 근거만 보고 sufficient / insufficient / none 을 판정 | **실습 1** |
| `route_after_grade` | 판정과 재검색 횟수로 다음 노드를 고른다. 상한을 지킨다 | **실습 1** |
| `calc` | 계산 질문이면 문서에서 파라미터를 뽑아 순수 함수를 부른다 | 완성본 (함수 하나는 **실습 3**) |
| `answer` / `abstain` | 근거만으로 답한다 / 거절 문구를 돌려준다. 문구는 `policy.yaml` | 완성본 |

셀 1 이 이 그림을 코드에서 뽑고, 셀 2 가 마스킹, 셀 3 이 `rewrite` 를 실제 LLM 으로 돌립니다.

## 실습 1 · `grade` 와 `route_after_grade`

`src/finrag/agent/nodes.py` 에서 둘을 채웁니다. 합쳐서 20줄 안팎입니다.

**먼저 읽을 것.** 파일 위쪽의 `GRADE`(프롬프트)와 `Grade`(스키마), `_context`, `policy()`, 그리고 `tests/test_agent.py` 의 grade 테스트 4개와 route 테스트 5개. 테스트가 곧 요구사항입니다. `docs/adr/ADR-004-agent-policy.md` 는 "왜 상한이 2인가, 왜 none 은 재검색하지 않는가"를 적은 완성본입니다.

**(a) `grade`.** 테스트 4개가 보는 것입니다.

1. 근거(`hits`)가 하나도 없으면 LLM 을 부르지 않고 `none` 입니다.
2. 근거가 있으면 `GRADE` 프롬프트에 질문(`masked_question`)과 근거(`_context(hits)`)를 넣어 `Grade` 스키마로 구조화 출력을 받고, 그 `verdict` 를 그대로 씁니다. `llm.with_structured_output(Grade, method="json_schema")` 가 그 도구입니다.
3. 키가 없으면(`is_fake(llm)`) 근거 분량만 봅니다. `policy()["retrieval"]["min_context_chars"]` 이상이면 sufficient, 아니면 insufficient. 판단이 아니라 자리 채우기입니다.
4. LLM 호출이 실패하면 `insufficient` 로 기웁니다. 근거가 있는데 `none`(거절)으로 보내면 오거절입니다.

**(b) `route_after_grade`.** 테스트 5개가 보는 것입니다. 3회차 노트북의 라우터와 같은 자리이고, 분기가 둘에서 셋이 됐습니다.

| 판정 | 재검색 횟수 < 상한 | 횟수 = 상한 |
|---|---|---|
| sufficient | answer | answer |
| insufficient | **retry** | answer (근거의 한계를 밝힌 답변) |
| none | abstain | abstain |

상한은 `get_settings().max_retries`(`.env` 의 `MAX_RETRIES`, 기본 2), 횟수는 `state.get("retry_count", 0)` 입니다. `grade` 가 아예 없으면 abstain 입니다.

```bash
make test
```

grade 4개와 route 5개가 초록이면 됩니다. 노트북 셀 4(실제 판정)와 셀 5(라우터 장난감)를 다시 실행하면 출력이 나옵니다.

## Self-Query · LLM 이 필터를 채운다

4회차 끝에 `search_demo --issuer 카카오뱅크 --latest` 로 판본이 섞이는 문제를 봤습니다. 필터를 사람이 넣었습니다. 오늘은 LLM 이 `QueryFilters` 스키마(`doc_type`, `issuer`, `product`, `generation`, `effective_on`)를 채웁니다. LLM 이 하는 일은 **그것뿐**입니다. Qdrant 필터로 바꾸는 일(`to_qdrant`)과 0건일 때 한 단계씩 푸는 일(`relax`)은 4회차에 본 `retrieval/filters.py` 의 코드가 합니다. 모델에게 필터 문법을 시키면 틀린 필드명을 지어내고, 그 순간 검색이 조용히 0건이 됩니다.

프롬프트(`selfquery.SYSTEM`)에 적힌 규칙 셋. 확실한 조건만 뽑고 모르면 비운다. "2013년 판 기준"은 날짜로, "현행"은 `latest` 로. "제31조" 같은 조항번호는 필터가 아니라 검색어다.

## 계산 · LLM 은 파라미터만 뽑고, 계산은 순수 함수가 한다

같은 "중도해지이율"인데 문서마다 산식이 다릅니다.

| 형태 | 산식 | 문서 |
|---|---|---|
| A 차감률형 | 기본이율 × (1 − 차감률) × 경과월수/계약월수 | 신한 |
| B 구간 적용률형 | 기준이율 × 적용률 × 경과월수/계약월수 | NH농협, KB |
| C 일할형 | 기본금리 × 적용률 × 경과일수/계약일수 | 카카오뱅크 |

여기에 셋이 겹칩니다. 구간표 첫 행이 산식이 아니라 고정값인 것(농협 "3개월 미만 0.1%"), 월 미만을 버리는 은행과 올리는 은행, 산출값이 최저보장보다 작으면 최저보장이 답인 것. 모델에게 "계산해 줘"라고 하면 이 중 하나를 빠뜨리고 **그럴듯하게 틀립니다.** 그래서 산식은 `src/finrag/tools/calc.py` 의 순수 함수에 두고, 모델은 문서에서 요율·구간·최저이율과 근거 조항을 뽑기만 합니다(`calc_node.ExtractedParams`). 필수 파라미터가 문서에 없으면 계산하지 않습니다. Tool 마다 무엇이 필수인지는 `tools/calc_specs.yaml` 에 있습니다.

## 실습 3 · `savings_early_termination_rate`

`src/finrag/tools/calc.py` 의 `savings_early_termination_rate` 를 채웁니다. 산식 셋을 한 함수로 받습니다. 25~30줄입니다.

**먼저 읽을 것.** 함수의 독스트링(산식 셋), 파일 위쪽의 `trunc_rate` 와 `CalcResult`, `_missing`, 그리고 `tests/test_calc_golden.py` 의 `test_c01` · `test_c02` · `test_c03`. 기대값은 `data/golden/calc_golden.jsonl` 에 문서 근거와 함께 있습니다.

**요구사항.** 테스트 3개가 보는 것입니다.

1. C01(농협, 형태 B): 기본 5.00%, 적용률 60%, 7개월/24개월 → 0.875%. 소수 셋째 자리 절사입니다.
2. C02(농협, 구간 고정값): `fixed_rate_pct=0.1` 이 오면 산식을 돌리지 않고 0.1% 입니다.
3. C03(카카오뱅크, 형태 C): 기본 2.00%, 적용률 50%, 120일/365일 → 0.328% 인데 최저보장 0.5% 보다 작아서 **0.5%** 가 답이고, 최저보장을 적용했다는 사실이 `warnings` 에 남아야 합니다.

그리고 세 가지 더. 기본이율이 없으면 `abstain_reason` 을 채운 `CalcResult(None, "%")` 입니다(지어내지 않습니다). 적용률 대신 차감률(`deduction_pct`)이 오면 곱하는 수는 `1 − 차감률` 입니다(형태 A). `steps` 에는 사람이 검산할 수 있게 계산 과정을 문장으로 남깁니다. 답변 노드가 그대로 인용합니다.

| 지표 | 뜻 | 하나만 보면 속는 이유 |
|---|---|---|
| 답변률(`answer_rate`) | 거절하지 않고 답한 비율 | 전부 답하면 100% 다 |
| 오거절률(`false_refusal_rate`) | 답할 근거가 있는데 거절한 비율 | 전부 거절하면 0% 가 아니라 100% 다 |

오거절률과 미답변 정확도를 **같이** 봅니다. 적대적 5문항은 거절했는지만 세지 않습니다. 문항마다 "하지 말았어야 할 것"(시스템 프롬프트 노출, 계좌번호 생성, 단일 수치 단정, 거래 실행, 없는 조항 긍정)이 답변에 나타났는지를 정규식으로 봅니다. 규칙은 `src/finrag/eval/adversarial.py` 에 있습니다. 통과 수를 채팅에 적어 주세요.
